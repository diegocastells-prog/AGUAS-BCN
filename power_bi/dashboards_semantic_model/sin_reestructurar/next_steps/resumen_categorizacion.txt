RESUMEN - Medidas de Categorización añadidas/corregidas en sm_aguas_bcn.SemanticModel
Archivo modificado: sm_aguas_bcn.SemanticModel/definition/tables/_medidas.tmdl

CONTEXTO
--------
Las medidas "vategoria_fuita" y "categoria_fraus" que ya existían en el modelo estaban
rotas: hacían referencia a una tabla "fact_anr_global_mensual" que ya no existe en el
modelo (no aparece en la carpeta de tablas ni en model.tmdl). Y "categoria_subcomptatge"
solo era un cociente (no una categoría de texto), por lo que la comparación
[categoria_subcomptatge] = "Subcomptatge" en "categoria_fraus" nunca era cierta.

Se reescribieron las 3 medidas usando el RTH y las tablas/medidas que sí existen
actualmente en el modelo, siguiendo tu especificación.

1) CATEGORITZACIÓ FUITES -> medida "categoria_fuites"
------------------------------------------------------
Regla pedida:
  Siempre que RTH < 90%. Si (∆Qmin - ∆Volum consumit > 2% o Zero Sensors Fuites Ortomat)

Cómo se implementó:
  - RTH -> medida existente [rth_distribucion_mensual]
  - ∆Qmin -> nueva medida [delta_qmin_mensual] = variación % de [q_min_mensual]
    respecto al mes anterior (mismo patrón que otras medidas "delta_..." del modelo)
  - ∆Volum consumit -> nueva medida [delta_volum_consumit_distribucion_mensual] =
    variación % de [volum_consumit_distribucion_mensual] respecto al mes anterior
  - Zero Sensors Fuites Ortomat -> SUM(dim_ortomat[unidad_sensors]) = 0
    (dim_ortomat es la tabla de sensores Ortomat por sector, columna unidad_sensors)

  DAX resultante (resumen):
    RTH < 0.9 && ( (DeltaQmin - DeltaVolumConsumit) > 0.02 || ZeroSensorsFuitesOrtomat )
      -> "Fuites"
      -> si no, "Sense Fuites"

  Supuesto: "∆" se interpretó como variación % mes contra mes anterior (mismo criterio
  que usan las demás medidas "delta_anr_mensual", "delta_volum_consumit_mensual", etc.
  del modelo).

2) CATEGORITZACIÓ SUBCOMPTATGE -> medida "categoria_subcomptatge"
-------------------------------------------------------------------
Regla pedida:
  Siempre que RTH < 90%. Si
  Σ(Nº Comptadors Q4⬆; Q1⬇; comp avariats; consum 0; comp estimades >3 periodes fact)
  / Σ Comptadors totals > 80%

Cómo se mapeó cada término a medidas/columnas del modelo:
  - Nº Comptadors Q4⬆        -> medida existente [compt_per_sobre_q4]
  - Q1⬇                      -> medida existente [compt_per_sobre_q1]
  - comp avariats            -> medida existente [comptadors_correctiu]
                                (contadores cambiados por avería/correctivo;
                                NO existe una columna "avariat" explícita en el modelo,
                                esto es un supuesto a validar contigo)
  - consum 0                 -> nueva medida [comptadors_consum_zero] =
                                DISTINCTCOUNT de polissa_subm en fact_dades_consum
                                donde dies_amb_consum_0 > 0
  - comp estimades >3 periodes fact -> medida existente
                                [subministraments_mas3_perÃ­odes_estimats]
                                (ya calculaba justo esto sobre fact_bossa)
  - Comptadors totals        -> medida existente [comptadors]
                                (COUNTROWS de fact_estadistiques_comp)

  DAX resultante (resumen):
    Numerador = Q4 + Q1 + correctius + consum_zero + estimades>3periodes
    Ratio = Numerador / Comptadors totales
    RTH < 0.9 && Ratio > 0.8 -> "Subcomptatge"
      -> si no, "Sense Subcomptatge"

3) CATEGORITZACIÓ FRAUS -> medida "categoria_fraus"
------------------------------------------------------
Regla pedida:
  Siempre que RTH < 90%. Por descarte, si no es FUITES y no es SUBCOMPTATGE.

  DAX resultante (resumen):
    RTH < 0.9 && NOT(categoria_fuites = "Fuites") && NOT(categoria_subcomptatge = "Subcomptatge")
      -> "Fraus"
      -> si no, "Sense Fraus"

PUNTOS A VALIDAR CONTIGO
--------------------------
  1. "comp avariats": se usó [comptadors_correctiu] (fact_estadistiques_comp,
     agrupacio_canvi = "Correctiu") a falta de una columna explícita de avería.
     Si existe otra fuente más adecuada, hay que ajustarlo.
  2. El umbral de "Zero Sensors Fuites Ortomat" se interpretó como que el sector
     (contexto de filtro actual) tiene 0 sensores instalados (SUM(unidad_sensors)=0).
     Confirmar si el criterio correcto es a nivel de sector o de otra granularidad.
  3. "∆Qmin" y "∆Volum consumit": se interpretaron como variación % respecto al mes
     anterior. Confirmar si en cambio se referían a otra comparación (p.ej. vs. mismo
     mes año anterior, o diferencia absoluta en vez de %).
